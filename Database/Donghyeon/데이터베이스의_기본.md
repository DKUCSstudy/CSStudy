- 데이터베이스는 일정한 규칙, 혹은 규약을 통해 구조화되어 저장되는 데이터 모음
- 해당 데이터베이스를 제어, 관리하는 통합 시스템을 DBMS(Database Management System)라고 함
- 데이터베이스 안에 있는 데이터들은 특정 DBMS마다 정의된 쿼리 언어(query language)를 통해 접근, 조작 가능

### 1. 엔터티

- 사람, 장소, 물건, 사건, 개념 등 여러 개의 속성을 지닌 명사
- 다른 엔터티의 존애 여부에 따라 종속적이라면 약한 엔터티, 독립적이라면 강한 엔터티라고 함

### 2. 릴레이션

- 릴레이션(relation)은 데이터베이스에 정보를 구분하여 저장하는 기본 단위
- 엔터티에 관한 데이터를 데이터베이스는 릴레이션 하나에 담아 관리
- 릴레이션은 관계형 데이터베이스에서는 '테이블'이라고 하며, NoSQL 데이터베이스에서는 '컬렉션'이라고 함

### 3. 테이블과 컬렉션

- 관계형 데이터베이스에는 레코드가 쌓여 테이블이 되고 테이블이 쌓여서 데이터베이스가 됨
- NoSQL 데이터베이스에는 도큐먼트가 쌓여 컬렉션이 되고 컬렉션이 쌓여서 데이터베이스가 됨

### 4. 속성

- 릴레이션에서 관리하는 구체적이며 고유한 이르을 갖는 정보
- '차'라는 엔터티를 예시로 들면 차 번호, 바퀴 수, 차 색깔, 차종 등이 있음

### 5. 도메인

- 릴레이션에 포함된 각각의 속성들이 가질 수 있는 값의 집합
- 예를 들어 성별이라는 속성이 있다면 이 속성이 가질 수 있는 값은 {남, 여}

### 6. 필드와 레코드

- 회원 엔티티로 member라는 테이블을 만듬다면
- 속성은 회원ID, 이름, 나이, 성별 등이 될 수 있음
- 필드는 name, ID, age, gender 등이 될 수 있음
- 테이블이 쌓인 행(row) 단위의 데이터를 레코드(=튜플)라고 함

### 7. 관계

1. 1:1 관계
   - 유저당 유저 이메일은 하나씩 있음
   - 유저 테이블, 유저 이메일 테이블로 나눈다면 1:1 관계
2. 1:N 관계
   - 한 유저당 여러 개의 상품을 장바구니에 넣을 수 있음
   - 유저 테이블, 상품 테이블로 나눈다면 1:N 관계
3. N:M 관계
   - 학생도 강의를 여러 개 들을 수 있고 강의도 여러 명의 학생을 포함할 수 있음
   - 학생 테이블, 강의 테이블로 나눈다면 N:M 관계

### 8. 키

#### 8-1. 기본키
   - ID와 같이 유일성과 최소성을 만족하는 키
   - 기본키는 자연키 또는 인조키 중에 골라 설정
   - 자연키
     - 중복되지 않는 것을 '자연스레' 뽑다가 나오는 키
     - 언젠가는 변하는 속성을 가짐
   - 인조키
     - 인위적으로 생성한 고유 식별자 (e.g., 시퀀스, UUID)
     - 자연키와 대조적으로 변하지 않음
     - 보통 기본키는 인조키로 설정함
#### 8-2. 외래키
   - 다른 테이블의 기본키를 그대로 참조하는 값으로 개체와의 관계를 식별하는 데 사용
   - 중복 가능
#### 8-3. 후보키
   - 기본키가 될 수 있는 후보들이며 유일성과 최소성을 만족 
#### 8-4. 대체키
   - 후보키가 두 개 이상일 경우 어느 하나를 기본키로 지정하고 남은 후보키들
#### 8-5. 슈퍼키
   - 각 레코드를 유일하게 식별할 수 있는 유일성을 갖춘 키
