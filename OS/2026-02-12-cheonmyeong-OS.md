# ✨ 학습 주제

- 과목: OS
- 주제: 3. 운영체제 (심화 및 상세 정리)

## 📄 학습 내용 요약

### 3.1 운영체제와 컴퓨터
#### 3.1.1 운영체제의 역할과 구조
- **역할**: 자원 관리(CPU 스케줄링, 메모리 관리), 프로세스 관리, 하드웨어 추상화, 시스템 보호 및 보안.
- **시스템 콜(System Call)**: 유저 모드 프로그램이 커널 자원을 사용하기 위해 운영체제에 서비스를 요청하는 인터페이스입니다.
- **유저 모드 vs 커널 모드(Dual Mode)**: CPU의 모드 비트를 활용하여 시스템의 안정성을 보장합니다. 커널 모드는 모든 자원에 접근 가능하지만 유저 모드는 제한됩니다.

#### 3.1.2 컴퓨터의 요소
- **CPU와 인터럽트(Interrupt)**: 하드웨어 장치가 CPU에 긴급한 통보를 보내는 메커니즘입니다. 인터럽트 발생 시 현재 작업을 중단하고 ISR(Interrupt Service Routine)을 실행합니다.
- **DMA(Direct Memory Access)**: CPU의 간섭 없이 입출력 장치가 메모리에 직접 접근할 수 있게 하여 CPU의 부하를 줄여주는 장치입니다.
- **시스템 버스**: CPU, 메모리, 입출력 장치 간의 데이터, 주소, 제어 신호를 전달하는 통로입니다.

### 3.2 메모리
#### 3.2.1 메모리 계층
- **계층 구조**: 레지스터 > L1/L2/L3 캐시 > 주기억장치(RAM) > 보조기억장치(SSD/HDD). 위로 갈수록 빠르고 비싸며 용량이 작습니다.
- **지역성(Locality)**: 캐시 성능을 극대화하는 원리로, 시간 지역성과 공간 지역성이 있습니다.

#### 3.2.2 메모리 관리
- **가상 메모리(Virtual Memory)**: 실제 물리 메모리보다 큰 프로그램을 실행하기 위해 보조기억장치 일부를 메모리처럼 사용하는 기술입니다.
- **페이지 폴트(Page Fault)**: 프로세스가 요청한 페이지가 물리 메모리에 없을 때 발생하는 인터럽트입니다. 이를 처리하는 과정에서 스와핑(Swapping)이 발생합니다.
- **스레싱(Thrashing)**: 잦은 페이지 교체로 인해 CPU 이용률이 급격히 떨어지고 페이징 작업에만 시간을 허비하는 현상입니다.
- **TLB(Translation Lookaside Buffer)**: 가상 주소를 물리 주소로 변환하는 속도를 높이기 위한 특수한 주소 변환 캐시입니다.

### 3.3 프로세스와 스레드
#### 3.3.1 - 3.3.4 프로세스 심화
- **컴파일 과정**: 소스 코드 → 전처리기 → 컴파일러 → 어셈블러 → 링커 → 실행 파일(.exe).
- **PCB (Process Control Block)**: 운영체제가 프로세스를 관리하기 위해 필요한 정보(PID, PC, 상태, 레지스터 값 등)를 담은 자료구조입니다.
- **문맥 교환(Context Switching)**: CPU가 한 프로세스에서 다른 프로세스로 전환할 때 기존 상태를 저장하고 새 상태를 로드하는 과정으로, 오버헤드가 발생합니다.

#### 3.3.5 - 3.3.6 멀티프로세싱과 스레드
- **IPC(Inter-Process Communication)**: 프로세스 간 데이터를 주고받는 메커니즘(공유 메모리, 메시지 큐, 파이프, 소켓 등)입니다.
- **멀티스레딩의 장단점**: 스택을 제외한 데이터/힙/코드 영역을 공유하여 자원 효율이 좋으나, 동기화 문제와 하나의 스레드 장애가 프로세스 전체에 영향을 줄 수 있습니다.

#### 3.3.7 - 3.3.8 공유 자원과 데드락
- **임계 영역(Critical Section)**: 공유 데이터에 접근하는 코드 영역. 상호 배제(Mutual Exclusion)가 필수입니다.
- **데드락 발생 4조건(Coffman)**: 상호 배제, 점유와 대기, 비선점, 환형 대기. 이 네 가지가 동시에 만족될 때 데드락이 발생합니다.

### 3.4 CPU 스케줄링 알고리즘
- **비선점형**: FCFS (선입선출), SJF (짧은 작업 우선 - 기아 현상 가능성), 우선순위 스케줄링.
- **선점형**: RR (Round Robin - 할당량 설정 중요), SRTF (최소 잔여 시간 우선), 다단계 피드백 큐 (MLFQ - 현대 OS의 기본).
